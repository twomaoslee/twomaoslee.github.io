# 会议日程管理后台

给会务组使用的精简工作台：搜索报告、修改草稿、核对差异后发布、查看版本并回退。网页和收藏地址继续是 https://zimin.li/agenda/ 。管理页面不会打包进参会网页。

## 会务组日常操作

1. 打开管理地址，以管理账号登录。
2. 输入报告编号或报告人，也可以先选会场。例如 `E63` 和 `E-063` 都能搜索。
3. 选择报告，修改需要的字段，点击“保存草稿”。可连续修改多场报告。
4. 点击“确认并发布”，逐项核对“修改前／修改后”，再确认发布。
5. 等待顶部显示“已上线”，可打开参会网站复核。显示“已提交”代表尚在等待部署。
6. 如需回退，先处理或清除草稿，再进入“版本记录”，选择旧版本，核对差异后“确认回退并发布”。回退会恢复整个所选日程版本中发生变化的报告；如只想撤回一条修改，直接编辑那一条更合适。

关闭网页不会删除已保存的草稿。多人使用同一账号时共享草稿；发生编辑冲突会拒绝覆盖，请先复制需要的文字，再刷新并重新编辑。编号、报告内部ID、类型与所属会场锁定；换报告、增删报告、整体场次重组由技术人员处理。时间和主持人只改选中条目，不自动改变整个场次。少数专题的结构化分项报告需由技术人员维护，相关字段会以只读方式显示。

## 本机启动（技术人员）

需要 Node.js 22 或更新版本、Git、对网站仓库的推送权限。本机可使用 GitHub CLI 的既有登录凭证，执行 `gh auth setup-git` 可配置 Git HTTPS 使用该凭证。

在网站仓库根目录运行：

```sh
node tools/agenda/admin/start.cjs --setup
node tools/agenda/admin/start.cjs
```

首次配置会要求输入两次至少14位密码，终端不回显。账号默认为 `admin`，可在首次配置时用 `AGENDA_ADMIN_USER` 环境变量改变。配置与草稿存储在用户主目录 `.local/share/cps2026-agenda-admin/`，权限为仅当前用户读取；不要提交或发送该目录。

默认地址 http://127.0.0.1:8790 ，只允许本机访问。重置密码后重启服务，原会话会失效。

服务维护自己的独立仓库副本；每次发布从远端最新主分支生成临时工作树，检查并构建后仅提交 `tools/agenda/source/data/` 和 `static/agenda/`。不会在技术人员的工作副本中执行重置或清理，不读取浏览器收藏。回退是新提交，保留完整历史，不执行 Git 强推。现有 GitHub Pages 工作流在主分支推送后自动部署。

## 源码和日程的唯一维护入口

仓库中的 `tools/agenda/source/` 是可移交源代码。数据为 `data/conference-latest.json` 和 `data/main-programs.json`。手工修改时先拉取最新仓库，编辑这些文件，运行以下命令再发布；不要直接编辑压缩后的 `static/agenda/conference-data.js`，也不要用旧 Excel 全量覆盖现有 ID。

```sh
node tools/agenda/source/validate.cjs
node tools/agenda/source/build.cjs
node --test tools/agenda/admin/*.test.cjs
```

构建保留旧哈希资源，报告内部ID和收藏键保持。其他会场的数据未变时会复用旧分片缓存。后台不会同步原生微信小程序。

## 远程部署（暂未配置）

给不在本机的会务组使用时，需要一个能运行 Node.js 与 Git、有持久磁盘、提供 HTTPS 的托管环境。GitHub Pages 只能运行参会静态网页，无法运行本后台。可以部署在会务组已有服务器，或注册云主机后配置；无需迁移现有域名或参会网页。

环境配置：

| 变量 | 用途 |
| --- | --- |
| `AGENDA_ADMIN_STATE` | 绝对路径，持久化配置、草稿、任务和仓库；建议 `/data/agenda-admin` |
| `AGENDA_ADMIN_HOST` | 远程容器可设 `0.0.0.0`，默认 `127.0.0.1` |
| `PORT` | 后台监听端口，默认 `8790` |
| `AGENDA_ADMIN_ORIGIN` | 公开管理地址，如 `https://agenda-admin.example.org`，需与反向代理保留的 Host 一致 |
| `AGENDA_ADMIN_REMOTE` | 网站仓库 Git 地址，默认当前个人主页仓库 |

仓库凭证在服务器的 Git 凭证配置或托管平台的秘密配置中设置，禁止放入网页、仓库、远端 URL 或聊天。GitHub 细粒度令牌仅授权所需仓库的 Contents 读写；这仍是仓库级权限，不能限制到某个文件夹。后台应用本身固定可编辑字段及发布路径，技术人员负责保管服务端凭证。不要把后台明文 HTTP 端口开放到公网。

登录使用 scrypt 密码哈希、8小时 HttpOnly/SameSite 会话、CSRF及来源校验、登录限流；重启需重新登录。单实例运行，草稿和任务持久化。多实例/多人权限管理需另做。部署前确认持久磁盘挂载和 HTTPS，配置账号，验证 Git 推送权限；设置服务开机启动并备份管理状态目录。初次迁移或升级先备份源数据。

## 已验证范围

自动测试使用独立临时仓库验证真实构建/推送/回退，测试不会修改正式日程；另覆盖未登录访问、CSRF、来源校验、限流、锁定字段、无效时段、草稿及确认失效、发布失败保留草稿、部署等待状态。版本记录展示最近30次日程数据提交，初次接入之前的发布不含可编辑源数据，因此只作为当前基线，不提供更早的数据回退。
